## Findings against CONTRACTS and the QA harness

Recorded here, not papered over.

1. `ParsedReferral` is named in CONTRACTS (`parseReferral(text): ParsedReferral | null`) but never defined. The reference defines it in `reference/types.ts` (version, memberId, plotId, date, n, counts{rust,cercospora,phoma,miner}, uncertain, answerId, confidence, decision). Engine agent should add it to CONTRACTS.
2. Plot id format. CONTRACTS example uses `P:2`. Lovable's `src/lib/parseReferral.ts` requires `^P\d{1,3}$` (`P07`). The reference accepts both (`^[A-Za-z0-9_-]{1,8}$`) and the suite tests both. One of the two must give way; CONTRACTS should state the plot id alphabet.
3. `buildReferral` signature. CONTRACTS says `buildReferral(c: Check)`; `kb/agents/engine.md` says `buildReferral(check, memberId)`. The reference follows CONTRACTS and reads `memberId` and `plotId` from `Check`. Missing values are written as `-` so the line still parses.
4. `Q:<conf%>` is not defined. Reference: mean confidence of accepted (non-unsure) leaves, rounded to a whole percent, 0 when no leaf was accepted. The suite only checks 0 to 100 and integer.
5. `X:<decision>` is required by the format but `Check.decision` is optional. Reference writes `ask` when missing. CONTRACTS should say so or make `decision` required at referral time.
6. `D:<yyyymmdd>` is read from `createdAt` in UTC in the reference so the output does not depend on the test machine. On a phone in Kenya (UTC+3) a check between 00:00 and 03:00 local time gets the previous UTC date. The engine may prefer local date; the suite accepts either only because random checks are generated at 06:00 to 18:00 UTC. Decide and state it.
7. `seasonWindow` uses the device's local calendar date in the reference. CONTRACTS does not say local or UTC.
8. Rule order in `rules.json` (mixed_problems before not_leaf) differs from the example in `kb/agents/content-voice.md` (not_leaf before mixed_problems). `rules.json` is authoritative and the suite follows it. With `uncertain_gte: 3` first, `not_a_leaf` can only be reached for plots of 4 leaves or fewer; for a 10-leaf plot a not_leaf majority always yields `too_many_unsure`. That is safe (both are "ask" or a retake) but means the `not_leaf` rule is dead for the normal flow. Capture-time retake (CONTRACTS last bullet) is the real path for not_leaf.
9. `decision_matrix.py` enumerates abstract tuples, not real plots. It sets `distinct = 1` for `healthy` and `none` plots (CONTRACTS: `distinctProblems` is 0 there) and includes states no leaf list can produce, such as `not_leaf` dominant with `uncertain = 0`. Harmless for the current rules (only `distinct_problems_gte: 2` is used) but a future rule on `distinct_problems_gte: 1` or on `not_leaf` with low uncertainty would be judged on impossible rows. The suite reproduces the Python enumeration exactly for the golden cross-check, and adds a second enumeration over all 8,008 real count vectors.
10. The catch-all `ask_officer` is reached in 15 of 3,510 abstract rows (dominant `none`, uncertain < 3) and in none of the 40,040 real 10-leaf decisions. For n = 10, `none` implies at least 5 unsure leaves, so `too_many_unsure` always wins. The only real path to the catch-all is an empty plot.
11. `AnswerCard.audio` is specified as `'/audio/sw/<id>.mp3'`. The reference emits a path only for languages that have text; nothing in CONTRACTS says whether to emit a path for missing languages. The suite asserts the reference behaviour (absent when no text).
12. Audio for `kind: nudge` answers: content-voice says SMS text only, no audio. `decide` never returns a nudge, so the suite does not cover it. If `play()` is called with a nudge id the engine should fall back to text silently (engine.md section 7).
